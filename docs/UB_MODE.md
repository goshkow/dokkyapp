# UB-режим: инженерное качество с доказательствами

Принципы ub-mode (Uncle Bob) в Докки сделаны механизмами, которые агент вызывает и которые меряют результат,
а не набором правил в промпте. Модель не вызывается ради метрик: CRAP, дубли, слои и мутации считаются
детерминированно на этом компьютере. Сеть, установка пакетов и `git push` не используются.

## Статусы гейта

`passed` - измерено и в норме; `failed` - измерено, нарушение; `skipped` - нечего проверять (нет изменённых
функций, нет политики слоёв, не входит в бюджет); `unavailable` - проверить не удалось (нет покрытия, базовый
прогон тестов красный, нет pytest); `cancelled` - остановлено; `error` - сбой самого гейта. `unavailable` никогда
не выдаётся за успех: итог хода пишет «не измерено» и почему.

## Когда гейты блокируют завершение

Автозапуск идёт перед завершением задачи в разработке по бюджету глубины. Блокирует только `failed` гейта из
списка `blocking` бюджета, один раз на версию кода и не больше общего лимита отказов. Мутации и сбор покрытия в
автозапуске выполняются, только если политика подтверждений разрешает запуск команд без вопроса.

## Как пользоваться

- Включить, выключить, выбрать глубину: Настройки → Разработка → «Объективные гейты».
- Политика слоёв: там же, «Слои архитектуры». Строка - слой от внутреннего к внешнему: `domain: src/domain/**`.
  «Предложить» строит разметку по графу импортов и показывает число нарушений до сохранения.
- Отчёт: правая панель → «Качество». Статусы гейтов с числами, находки с переходом к строке, «Принять» /
  «Исправить» для дублей, выживших мутантов и нарушений слоёв, журнал решений агента, предложения слоёв.
- Ручной запуск: кнопки «Проверить» (сигналы, CRAP, дубли, слои) и «Мутации» в карточке; агент - `quality.run`.
- Тепловая карта: «На карте» в карточке подсвечивает файлы с долгом на карте проекта.
- Старые worktree: Настройки → Разработка → «Рабочие копии» → «Проверить», затем «Убрать».

## Бенчмарк

`python scripts/benchmark_quality.py` - раздел `ub_gates`: 8 фикстур (чистая правка, сложная функция,
переименованный дубль, слабые и сильные тесты под мутациями, нарушение слоя, проглоченная ошибка, красный базовый
прогон). Для каждой - что показала прежняя проверка (`qa.run`: линт и тесты) и что показали гейты, время гейтов.

## Ограничения

- Языки: Python, TypeScript/TSX, JavaScript. Для JS/TS функции и мутанты ищутся по замаскированному тексту без
  полного парсера - уверенность `heuristic`.
- Мутации запускают тесты проекта: время растёт с числом мутантов; бюджет и таймауты ограничивают, но медленный
  набор тестов даст `unavailable` по времени.
- Сигналы - повод посмотреть строку, а не доказанный дефект; ложные срабатывания возможны.
- Замок одного писателя живёт в памяти сервера: два отдельных сервера на одной папке он не разведёт.
